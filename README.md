# 产品目录 RAG 助手（飞书机器人 + 网页）

> **演示数据均为虚构，不代表任何真实客户项目。** 分销商「瑞丰机电批发（虚构）」、20 份规格书、价目表、FAQ、客户协议价全部为生成数据；
> 300 个 SKU 和 8 家客户的协议价沿用同一虚构分销商的订单录入演示。

批发企业的销售和客服每天被问“这个型号外径多少”“没货了换哪个”“给某客户报个价”。答案散落在几十份 PDF 规格书、一张价目表和一份 FAQ 里。
这个项目把它们做成一个**带出处的问答助手**，在飞书里 @ 它或在网页里提问即可：

- **每个回答都标出处**：文档名 + 页码（PDF）/ 行号（价目表）/ 条目号（FAQ），点开就能看原文片段。
- **资料里没有就拒答**，不编造参数（评测集里 7 道目录外问题）。
- **角色权限**：销售能看价格、能出报价草稿；客服看不到价格——价目表片段在检索之前就被过滤掉，模型根本拿不到。
- **替代型号**：按规格书第 6 节的替代规则，从结构化目录里匹配候选（例如 6205-2RS → 6205-ZZ），再由模型解释替代条件并引用原文。
- **生成报价草稿**：模型只负责把“给沪东衡砺报个价：6204-2RS 200个……”解析成结构化请求；价格按客户协议价 → 目录价的规则确定性计算，
  含包装换算、目标价容差、信用额度、运费提示，输出 Excel 草稿，不会自动发给任何人。
- **筛选**：型号 / 材质 / 尺寸 / 价格区间（价格筛选仅销售）。
- **查询日志与调用追踪**：每次提问记录角色、检索结果、引用、每个阶段的耗时、tokens 和估算费用（SQLite）。
- **两家模型**：回答生成可在 DeepSeek 与通义千问（百炼）之间用环境变量切换；向量和重排用百炼。
- **评测**：50 道题在实现之前写定，三种检索配置各实测一次，另用通义千问 qwen-plus 实测一次；真实模型输出全部录制，可离线零费用回放。

## 快速开始

需要 Python 3.10+（开发环境 Python 3.15 / Windows 11）。

```powershell
pip install -r requirements.txt

# 不需要任何 key：回放模式，只使用 data/replay/ 里真实调用的录制结果和向量缓存
python -m catalog_rag ingest                       # 解析文档、建索引（向量全部命中缓存，0 次接口调用）
python -m catalog_rag ask "6205-2RS 缺货，有什么可以替代？" --role 客服
python -m catalog_rag ask "有哪些 316 材质的球阀？" --material 316 --price-max 150
python -m catalog_rag eval                         # 三种检索配置 × 50 题，回放结果写到 out/eval_replay/
python -m catalog_rag web                          # 打开 http://127.0.0.1:8780
python -m unittest discover -s tests -t .          # 68 个测试，不联网
```

回放模式只能回答录制过的问题（评测集 50 题和上面的示例）；新问题会明确报“回放模式下没有这个请求的真实录制结果”。
要问任意问题，设置 key 进入 live 模式：

```powershell
$env:DASHSCOPE_API_KEY = [Environment]::GetEnvironmentVariable('DASHSCOPE_API_KEY','User')
$env:LLM_API_KEY       = [Environment]::GetEnvironmentVariable('LLM_API_KEY','User')
python -m catalog_rag ask "6302-ZZ 的内径和极限转速是多少？" --role 客服
```

| 命令 | 作用 |
|---|---|
| `python -m catalog_rag ingest` | 解析 `data/docs`，写 `data/index/`（片段、结构化目录），缺的向量调用百炼计算并追加到缓存 |
| `python -m catalog_rag ask "<问题>" [--role 销售\|客服] [--model --material --size --price-min --price-max]` | 命令行提问 |
| `python -m catalog_rag web [--port 8780]` | 本机网页聊天：引用可点开看原文、打开 PDF 对应页、下载报价 Excel、看调用追踪和查询日志 |
| `python -m catalog_rag bot` | 飞书机器人（长连接） |
| `python -m catalog_rag eval [--pipeline bm25\|hybrid\|hybrid_rerank\|all]` | 50 题评测；live 结果写 `evaluation/`，回放结果写 `out/eval_replay/` |
| `python tools/make_data.py` | 重新生成全部演示文档和 `data/catalog_truth.json`（确定性，测试会校验与仓库内文件逐字节一致） |

## 飞书机器人

使用飞书自建应用的**长连接**事件订阅（`lark_oapi.ws.Client`），不需要公网地址或回调 URL。应用需要：机器人能力、事件 `im.message.receive_v1`、
权限 `im:message:send_as_bot`、`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`。

```powershell
$env:FEISHU_APP_ID     = [Environment]::GetEnvironmentVariable('FEISHU_APP_ID','User')
$env:FEISHU_APP_SECRET = [Environment]::GetEnvironmentVariable('FEISHU_APP_SECRET','User')
$env:DASHSCOPE_API_KEY = [Environment]::GetEnvironmentVariable('DASHSCOPE_API_KEY','User')
$env:LLM_API_KEY       = [Environment]::GetEnvironmentVariable('LLM_API_KEY','User')
$env:FEISHU_DEFAULT_ROLE = "销售"      # 只有自己用时；默认是 客服（最小权限）
$env:FEISHU_ALLOW_ROLE_TAG = "1"       # 演示用：消息以 #客服 开头即按客服角色回答
python -m catalog_rag bot
```

- 单聊直接发；群聊里 @机器人。回复以“回复原消息”的方式发在同一个会话里，开头注明本次使用的角色。
- 忽略机器人/应用自己发的消息；同一事件或同一消息被飞书重投时只处理一次（事件回调立即返回，回答在工作线程里生成）。
- 角色：`FEISHU_USER_ROLES="ou_xxx:销售,ou_yyy:客服"` 按 open_id 指定，其余用户用 `FEISHU_DEFAULT_ROLE`。
- 消息里可以写筛选：`有哪些球阀 材质:316 价格:0-150`。发“帮助”看用法。
- 查询日志里只存 open_id 的 SHA-256 前 12 位，不存原始 ID。

**实机验证（2026-11-18，飞书单聊，`CATALOG_PIPELINE=bm25` + `deepseek-flash`，默认角色客服）：**

| 在飞书里发的消息 | 机器人在同一会话里的回复（摘要） | 耗时 |
|---|---|---|
| 6204轴承2RS和ZZ有什么区别？ | 尺寸、材质相同；2RS 双面胶封、极限转速 9700 r/min，ZZ 双面铁封、14900 r/min；可互换及选型建议。附出处：RF-01_深沟球轴承规格书.pdf 第2页、第4页 | 2.2 s |
| 6204-2RS多少钱一个？ | 当前角色（客服）无权查看价格信息，请联系对接销售。（权限检查在检索前，未调用模型） | 0.0 s |
| 你们卖电动叉车吗？ | 目录资料中没有电动叉车方面的信息（并说明目录里有哪些相关品类），没有编造 | 1.3 s |

三条都以"回复原消息"的方式回到飞书，开头注明角色。混合检索与重排在飞书里没有实测（当时百炼账户欠费，之后已充值，只在评测里实测过）。

完整报告（含逐题答案、引用、检索结果、每阶段耗时）：`evaluation/bm25__deepseek-flash.md`、`evaluation/hybrid__deepseek-flash.md`、
`evaluation/hybrid_rerank__deepseek-flash.md`、`evaluation/hybrid_rerank__qwen-plus.md` 和同名 `.json`。

第一次跑“混合+重排”时，百炼账户在第 50 题返回 `Arrearage`（欠费）。充值后整列重跑，表中是重跑的结果，那次的报告和录制已删除。

怎么读这张表：

- **分数高，主要因为数据是合成的。** 文档和题目出自同一个人，提问大多带精确型号（6204-2RS、CJX2-2510），表格解析是逐字准确的（300/300 行），
  BM25 按字符二元组 + 型号整词就能命中。hit@5 按“页”判定：表格页上有几十行，命中同一页不等于命中那一行，比按行判定宽松。
  这些数字说明流程是通的，**不能当作真实客户资料上的准确率**；真实项目需要用客户自己的资料和问题重新测。
- **在这套题上，向量检索没有带来提升。** 唯一的差别 D2（“YE3 3kW 4极电机的标准交期是几天？”）：混合检索把电机规格表的 5 行排在前面，
  价目表那一行掉出前 5，模型看不到交期于是如实拒答；重排后又回到前 5。表格行之间只差几个数字，512 维向量几乎分不开它们。
  混合检索的价值在口语、同义词和没有型号的问题上，这套题里这类题太少（6 道口语题三种配置都答对了），区分不出来。
- **延迟要按阶段看**（来自查询日志的每阶段耗时）：查询向量化约 1.2 s（本机到百炼北京地域），重排约 1.4 s，DeepSeek 生成约 1.5 s，
  qwen-plus 生成约 2.6 s。两列“混合+重排”运行时，查询向量已经在“混合”那次运行里算过并缓存，所以表中这两列的延迟**不含向量化**；
  不走缓存时实际约再加 1.2 s，即 DeepSeek 约 4.1 s、qwen-plus 约 5.1 s。
- **E4 是 DeepSeek 三列共同的错题**（客服问“可以申请免费样品吗？有什么条件？”）：FAQ 原文是“单价 200 元以下的物料可申请”，
  DeepSeek 每次都因为提示词里“客服不要出现价格”的规则把“200 元”这个门槛省掉了，改成“请向销售确认”，权限规则在这里过度生效了。
  qwen-plus 照原文答出了这个门槛。按约定没有为此改提示词。
- **qwen-plus 与 DeepSeek 对比**（同一检索结果）：正确率相同（49/50），错题不同。qwen 的 A8 只答了“NPN”，漏掉“常闭”。
  qwen 回答更短：输出 tokens 约为 DeepSeek 的三分之一，引用也更少更准（64 处、精确率 98.4%）。但生成更慢，约 2.6 s 对 1.5 s。
  每题估算费用两者相近；qwen-plus 单价没在官网核实。DeepSeek 这一列费用低，是因为输入的 75% 命中了它的提示词缓存，而且是在非高峰时段跑的。
- **引用精确率**没到 100% 的几处（例如 D3 同时引用了规格书里的“100件/箱”、B6 引用了 FAQ“质保期见规格书”）其实也是相关来源，
  只是不在题目列出的可接受来源里——可接受来源写得偏窄。
- **资料外数字提示**：BM25 的 live 报告有 1 题被标记，是 G1 的“150”：这个数来自筛选条件，不在资料片段里，属于检查器误报，跑完后已修复（筛选条件文字也计入资料）。
  qwen-plus 列有 1 题被标记，是 E1 的“17”：模型把“下午五点”写成“17:00”，属于正常推算，提示保留。

### 不花钱复现

真实调用的原始返回在 `data/replay/` 目录：226 个文件，共 276 次调用。每个文件记录 `source: live`、接口、模型和请求原文；
每次调用记录 `recorded_at`（2026-11-18，UTC）、`run`（哪次运行发出的，格式为“检索配置/回答模型”）、`latency_ms` 和原始响应（含 usage）。
向量缓存 `data/index/embedding_cache.jsonl` 有 814 条，同样标注 `source: live` 和时间，兼作向量的回放记录。

```powershell
$env:CATALOG_MODE="replay"; python -m catalog_rag eval
$env:LLM_PROVIDER="qwen"; python -m catalog_rag eval --pipeline hybrid_rerank
```

回放结果与 live 报告逐题比对：四份报告的 200 个答案、引用、检索结果和回答模型的 tokens 完全一致。只有一处已知差异：
向量来自缓存，回放不包含查询向量化的耗时，所以“混合”列的回放延迟比实测低约 1.2 s。延迟以 `evaluation/` 下的 live 报告为准。

关于录制标签：不同运行有时会发出逐字节相同的请求。例如 BM25 和混合检索取到完全相同的 5 个片段，或者 DeepSeek 列和 qwen 列发出同一个重排请求。
录制器原先把这些调用追加在同一个文件里，不区分来源，回放时会张冠李戴，qwen 列因此有 3 题对不上。现在每次调用都带 `run` 标签。
已有记录的标签是按各次运行的结束时间（报告里的 `run_at`）补上的。

### 评测之后改过的代码（如实列出）

BM25 和混合两列是用下面这些改动之前的代码跑的；两列“混合+重排”是用改动之后的最终代码跑的。用最终代码回放 BM25 和混合两列，50 题的答案与当时完全一致。

- 资料外数字检查把筛选条件文字也算作资料（修复 G1 误报）；只影响提示，不影响任何得分。
- 向量 / 重排出错时降级（由百炼欠费暴露）。
- 录制文件加 `run` 标签（见上）。
- 产品型号匹配从“按字符长度计覆盖率”改为“按词数”：单元测试发现“BV 2.5平方”时红色和黄绿色候选没有打平。
- 开发过程中用假模型把评测脚本空跑过一次（检验脚本本身），那次用的是真实 BM25 检索，因此 BM25 的 hit@5 在正式运行前已经看到过；之后没有改检索。

## 关键设计

**切块。** PDF 按页解析（pypdf layout 模式），出现在几乎每一页的行视为页眉删除，“第 n 页 / 共 m 页”删除。正文按“章节 × 页”成块；
表格识别“表N 标题 + 表头 + 同列数的行”，每一行单独成块并带上文档标题、表名和表头（“型号 6204-2RS；物料编码 1.01.0009；内径d(mm) 20；…”），
续表页的行同样自描述，引用到行所在的页。价目表每行一块（带表头），价格政策每条一块；FAQ 每问一块。共 766 块。

**检索。** BM25（无分词器：CJK 单字+二元组，型号整词及其拆分，例如 `6204-2rs`/`6204`/`2rs`；“平方→mm2”“4极→4p”两条同义写法在写题前加入）；
百炼 `text-embedding-v4`（512 维）余弦相似度；两路各取前 30 用 RRF（k=60）融合；取融合前 20 交给 `gte-rerank-v2`，取前 5（有筛选时前 10）。
**权限和筛选在排序之前生效**：先按角色和筛选条件算出允许的片段集合，再在集合里检索。客服角色下价目表片段不进入候选，也就不可能进入提示词。

**回答与拒答。** 模型按 JSON 输出 `{answerable, answer, citations}`，Pydantic 校验，失败把错误原文喂回去重试一次。资料不能回答时 `answerable=false`，
直接作为拒答返回。文中 `[n]` 和 `citations` 合并后映射回片段（文档+页码/行号）；引用了不存在的编号会被删除并提示；没有引用会提示人工核对；
回答中出现资料里没有的数字会提示；客服角色下这类数字若带“元/¥”会被屏蔽。

**替代型号。** 结构化目录（从规格表行 + 价目表行解析得到，不是从生成器读）按品类的替代规则匹配候选：同尺寸异密封（轴承）、同尺寸异材质（O 型圈、球阀）、
同线圈电压大一档（接触器）等，规则与规格书第 6 节一致；没有规则的品类（断路器、熔断器、电机……）不给候选。候选的规格行和第 6 节原文一起放进资料，
由模型说明替代条件并引用。

**报价草稿。** 模型只做解析（客户名、型号原文、数量、单位、目标价）；之后全是确定性规则：型号匹配（唯一才报价，有歧义列出候选让人选）、
客户匹配（名称最长公共片段 ≥ 4 字且唯一）、价格 = 客户协议价，没有则目录价（与订单录入演示同一规则）、内件数换算成箱（非整箱向上取整并提示）、
目标价偏离协议价超过 ±2% 提示需审批、应收余额 + 报价超过信用额度提示、不满 3000 元提示运费。草稿存为 `out/quotes/Q-日期-哈希.xlsx`。

**日志与追踪。** 每次提问一行 SQLite（`out/query_log.db`）：渠道、用户哈希、角色、问题、筛选、意图、检索配置、状态、答案、引用、检索结果（含各路排名和分数）、
警告、每个阶段（bm25 / embed_query / vector / rerank / generate / quote_parse）的耗时、tokens、估算费用。网页右侧可以看到。

## 局限（如实说明）

- 数据是合成的、版式规整，文字层完整；没有扫描件、没有合并单元格、没有跨页断行的表格行。真实规格书需要 OCR 和更强的表格解析。
- 评测集 50 题、同一人编写，覆盖面有限；分数说明流程可用，不代表真实场景准确率。hit@5 按页判定，比按行宽松。
- qwen-plus 只在“混合+重排”这一种配置上实测过一次。
- 飞书往返只用 BM25 + DeepSeek 实测过 3 条消息（见"飞书机器人"）；机器人在本机长连接运行，未做多实例部署（去重只在进程内存里）。
- `CATALOG_PIPELINE=bm25` 搭配 DeepSeek 时只需要 `LLM_API_KEY` 就能实时运行；混合检索、重排或千问回答才需要百炼 key。
- 网页端没有登录，角色由页面下拉框选择，只适合本机演示；正式使用应从飞书通讯录或 SSO 取角色。
- 权限只到“价格可见与否”两档；没有按客户、按品类的数据权限。
- 替代规则写在代码里，与规格书第 6 节人工对齐；换一家客户需要重新整理规则。
- 回放模式只能回答录制过的问题。
- 估算费用依赖公开单价，其中重排和 qwen-plus 的单价未在官网核实；实际扣费以控制台为准。
